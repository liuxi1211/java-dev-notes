# Task Capture — 新增代办任务

把用户描述的任务自动写入任务管理目录下对应当月的任务文件。

> 本 skill **可被任意项目调用**，任务永远写入下面的固定路径，不写入调用方项目目录。

---

## 0. 固定路径

```
笔记本根目录：d:\javaApp\Obsidian\workspaces\java-dev-notes
任务目录：14-任务管理/
月度文件格式：YYYY-MM月任务.md（如 2026-08月任务.md）
```

- 所有任务必须写入 `14-任务管理/` 目录下的月度文件。

## 1. 触发条件

用户显式表达"添加任务"的意图，关键词（中英）：
- "加个任务" / "新增任务" / "加个待办" / "帮我记个任务" / "任务加一下"
- "add task" / "add todo" / "new task"

同时，如果上下文明显是在讨论任务管理且用户给出了具体待办内容，也可直接执行。

---

## 2. 任务信息提取

从用户描述中提取以下信息：

| 字段 | 必填 | 说明 |
|---|---|---|
| `description` | ✅ | 任务描述 |
| `due_date` | ✅ | 截止日期（用户没说就追问） |
| `priority` | ❌ | 优先级：`high` / `medium` / `low`，默认 `medium` |
| `start_date` | ❌ | 开始日期，用户提到了才加 |
| `category` | ❌ | 分类：`工作任务`  / `其他`，根据内容自动判断，默认 `工作任务` |

### 日期解析规则

- 相对日期按当前日期（`Today's date`）换算：
  - "今天" → 今日
  - "明天" → 今日 +1
  - "后天" → 今日 +2
  - "本周五" / "周五" → 本周的周五（如果今天已经过了周五，就是下周五）
  - "下周一" → 下周一
  - "月底" → 当月最后一天
  - "周五前" → 本周四
- 绝对日期直接用：如 `8月20号` → `2026-08-20`
- 只有日期没有月，默认是当前月；如果当前月已过，是下个月
- 只有月份没有日，默认该月 15 号

如果用户描述模糊到无法确定截止日期，**直接问**，不要猜。

### 优先级判断

用户没说优先级就默认 `medium`（🔼）。以下情况自动调高：
- 用了"紧急"、"马上"、" ASAP "、"重要" → `high`（🔺）
- 用了"不急"、"有空再说"、"随便" → `low`（🔽）

---

## 3. 写入哪个文件

按 **截止日期的月份** 决定写入哪个月度文件：

- 截止日期在 8 月 → 写入 `2026-08月任务.md`
- 截止日期在 9 月 → 写入 `2026-09月任务.md`

**文件不存在则自动创建**，结构参考已有月度文件：
```markdown
# YYYY-MM月任务
---
## 本月重点

- 

---

## 工作任务

- [ ] 

---

## 其他

- [ ] 
```

---

## 4. 任务行格式

使用 Tasks 插件的 emoji 语法：

```
- [ ] {优先级emoji} {描述} 🛫{开始日期} 📅{截止日期}
```

各部分用空格分隔，顺序尽量统一：优先级 → 描述 → 开始日期（有就加）→ 截止日期 

### 优先级 emoji 映射

| 优先级 | emoji |
|---|---|
| high | 🔺 |
| medium | 🔼 |
| low | 🔽 |

### 日期格式

- 开始日期：`🛫 YYYY-MM-DD`
- 截止日期：`📅 YYYY-MM-DD`

---

## 5. 写入位置

在月度文件中，按分类找到对应章节，**追加到该章节的任务列表末尾**：

- 分类 = 工作任务 → 追加到 `## 工作任务` 下
- 分类 = 其他 → 追加到 `## 其他` 下

**重要**：不要破坏已有任务的结构，不要重新排序，不要删除任何已有内容。

---

## 6. 执行流程

1. **提取信息**：从用户描述中提取任务描述、截止日期、优先级、分类等。
2. **确认信息**：如果关键信息缺失（特别是截止日期），先问清楚再执行。
3. **确定目标文件**：根据截止日期月份确定月度文件路径。
4. **检查文件**：读取月度文件，如果不存在则按模板创建。
5. **写入任务**：在对应分类章节末尾追加任务行。
6. **回复用户**：简洁告知结果，包括任务内容、截止日期、写入位置。

---

## 7. 回复格式

成功后回复：

```
✅ 任务已添加
📝 内容：{任务描述}
📅 截止：{截止日期}
🔺 优先级：{high/medium/low}
📂 位置：14-任务管理/{月度文件名}
```

如果需要用户确认信息，用自然语言问就好，不要用表格。

---

## 8. 示例

### 示例 A — 简单任务

用户："加个任务，周五前完成周报"

- 描述：完成周报
- 截止日期：本周五
- 优先级：medium（默认）
- 分类：工作任务
- 目标文件：`2026-08月任务.md`（假设周五在 8 月）

写入：
```markdown
- [ ] 🔺 完成周报 📅 2026-08-22
```

### 示例 B — 带优先级的任务

用户："加个紧急任务，今天要把线上 Bug 修了"

- 描述：修复线上 Bug
- 截止日期：今天
- 优先级：high（紧急）
- 分类：工作任务

写入：
```markdown
- [ ] 🔼 修复线上 Bug 📅 2026-08-17
```

### 示例 C — 学习任务

用户："加个学习任务，这个月把 Spring AOP 源码看完，不着急"

- 描述：看完 Spring AOP 源码
- 截止日期：本月底
- 优先级：low（不着急）
- 分类：学习任务

写入：
```markdown
- [ ] 🔽 看完 Spring AOP 源码 📅 2026-08-31
```

### 示例 D — 跨项目

用户在业务项目仓库里说："加个任务，月底前完成支付模块重构，高优"

- 描述：`[支付项目] 完成支付模块重构`
- 截止日期：本月底
- 优先级：high

---

## 9. 反例（不要这样做）

- ❌ 用户没说加任务，主动创建任务
- ❌ 截止日期不明确时瞎猜（应该问）
- ❌ 把任务写到技术笔记文件里（必须写进 `14-任务管理/` 的月度文件）
- ❌ 写入时删除或重排已有任务
- ❌ 月度文件不存在时不创建，直接报错
- ❌ 用 Tasks 插件不支持的 emoji 或格式

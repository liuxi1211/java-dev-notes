# AI 股票分析 SaaS — 项目总览

> **项目背景**：个人已用 Claude Code + 金融 MCP（行情/财报/公告等数据源）+ 全链路股票分析 Skill（涨跌分析、板块分析、个股研判、三表预测等）跑通了单用户分析工作流。本项目目标是将其**产品化为面向 C 端用户的在线 SaaS 服务**。
>
> 核心论断：个人跑通的东西和线上产品之间，隔的不是"部署"，而是"重构"。Skill 和 MCP 不能直接搬上生产，但其价值在于已验证了"场景 → 数据 → 分析框架"这条链路，要做的是把它工程化固化为代码。

## 个人环境 vs 线上产品的映射关系

个人跑通的链路：`提问 → Claude Code 意图识别 → 匹配 Skill → Skill 调 MCP 拿数据 → AI 分析输出`

这四环里只有"分析框架"的知识是资产，其他三环都是 Claude Code 工具替你干的，上线时全要重写：

| 个人环境 | 线上产品 | 重构要点 |
|---|---|---|
| Claude Code 自动匹配 skill | 意图路由服务 | MVP 阶段 UI 显式选场景（命中率 100%），自由输入后开 LLM 路由 |
| 各个 skill 文件 | 场景流水线（代码化 DAG） | 每个 skill 固化为：取数步骤 + 数据处理 + Prompt 模板 + 输出结构 |
| MCP 数据源 | 数据访问层（内部服务） | MCP 是个人工具协议，生产上封装为内部 API |
| 终端会话 | 无状态 API + Redis 会话 | 多租户隔离、上下文管理、SSE 流式输出 |

## 场景定位：企业 AI 落地全景中的位置

按"通用 → 垂直"与"效率工具 → 业务核心"两个维度看当前企业 AI 落地格局：

- **第一梯队（红海）**：智能客服/知识库问答、办公提效（周报/纪要/文案）
- **第二梯队**：AI 代码助手、ChatBI、文档智能处理（合同/票据审查）
- **第三梯队（玩家少）**：金融投研/风控、医疗辅助诊断、工业质检

本项目 = **ChatBI 的数据链路 + 投研领域的垂直知识 + Copilot 转 Autopilot 的交付形态**。前两者是资产，第三者是门槛：

| | Copilot 模式 | Autopilot 模式 |
|---|---|---|
| 服务对象 | 内部员工 | 外部客户 |
| 错误容忍度 | 高（人会把关） | 低（用户直接消费结论） |
| 合规压力 | 小 | 大 |
| 典型代表 | 代码助手、办公提效 | 本项目、AI 投顾 |

个人使用时是 Copilot 模式（自己是把关人），做成 C 端产品后瞬间变成 Autopilot 模式——错误容忍度、合规要求、质量标准全部换档。这就是必须建 eval 体系和合规过滤器的根本原因。

另外，这套东西的本质是"领域专家把自己的决策流程 SOP 化"——每个 skill 就是一段可复用的专家经验，对应行业术语 **Agentic Workflow（智能体工作流）**，是 2025-2026 年企业 AI 落地的第二波主战场（第一波是 RAG 问答）。

## 三个必须最先回答的非技术问题

1. **合规是生死线**：C 端个股分析/推荐在境内属证券投资咨询业务，需牌照。无牌照只能做"信息展示与数据整理"，不能给买卖建议。输出层必须加合规过滤器（拦截"买入/卖出/目标价"等表述），Prompt 全部改写为"数据显示/历史规律表明"。
2. **数据源商业授权**：Wind / iFinD 个人 license 禁止转售。要么谈商业分发授权（贵），要么换可商用源。
3. **这两个问题不解决，架构做得再好也上不了线**——建议公司层面先立项确认，再动代码。

## 分阶段路线

- **P1 MVP**：挑 3-5 个高频场景（个股速览、板块异动、涨跌归因），UI 显式选场景，SSE 流式 + 合规过滤 + 简单配额。目标验证有人愿意用，不是功能全。
- **P2**：意图自动路由（LLM 分类兜底）、场景扩展全量、付费配额体系、MQ 异步深度报告。
- **P3**：场景配置化（运营不发版上线新场景）、多模型路由、完整 eval 体系。

## 技术栈速查

| 组件 | 选型 |
|---|---|
| 编排层 | Spring Boot 3 + Spring AI 1.x（自研轻量 DAG，不上重框架） |
| 流式输出 | SSE（SseEmitter / WebFlux） |
| 存储 | MySQL + Redis（会话/缓存）+ 可选向量库 |
| 异步长任务 | RocketMQ + Temporal（durable execution） |
| 观测 | OpenTelemetry + 节点级 span |

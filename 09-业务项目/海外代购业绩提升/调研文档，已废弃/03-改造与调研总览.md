## 一、改造点

### A. 数据与供给底座（决定天花板）

#### A1 商品中心化（地基）

- **做什么**：把"型号"立为一等公民，供应商报价降为挂在型号下的 Offer。
- **怎么做**：建商品主数据（SPU）+ 型号归一化（后缀归一、品牌别名、料号交叉引用、AI 匹配 + 人工纠偏）；系统记录用关系库，搜索降级为投影；事件驱动增量更新替代全量重建。
- **解决什么**：根因二（选错原子单位）——当前 26 个供应商索引各搜各的、映射做了搜索没用上，导致跨供应商比价/聚合库存/最优渠道/替代料全做不出来。

#### A1 治理定位：全量聚合 + 透明标注 + 用户自筛

- **做什么**：明确中心化的目的不是替用户删数据，而是让同型号"排到一起"。
- **怎么做**：全部供应商数据接入不删；数据质量三评分（完整度/新鲜度/可信度）只用于默认排序权重和"更新于 X 小时前" 标注；供应商始终保留可筛选；清洗只针对脏记录和全无活跃报价的幽灵型号，不因数据陈旧清除真实供应商。
- **解决什么**：避免"替用户择优汰换"误伤认准某家供应商的客户，同时给无主见用户好默认值、给有主见用户完全控制权。

#### A1+ 撮合交易（聚合展示 + 拆单履约 + 分级确认）

- **做什么**：解决"客户要 1w、两家各 5k"的拆单撮合，以及"去供应商官网下单有人工、要时间"的体验问题。
- **怎么做**：库存按置信度分层展示（可承诺/待确认/询价）；一个客户单拆成多张采购单、状态逐段透明；整单等齐/部分先发/尽力拼凑三种模式让客户选；缺货先自动找下家（fallback）再降级协商；复杂单转人工通道给 SLA。
- **解决什么**：商城要么少卖（挂 5k）要么超卖跑单（挂 1w）的两难；把人工采购耗时诚实落入确认时效，而非冒充现货。

#### A1++ 数据时效改造（MQ 事件总线 + 增量更新 + 热门商品池）

- **做什么**：消灭 T+1 全量重建、夜间窗口、队列丢数据，让数据快速生效并精准投频采集。
- **怎么做**：①爬虫/接口拿到数据即发 MQ、增量写库刷索引、本次生效（配幂等/重试/死信/背压）；②增量更新替代全量蓝绿重建，全量降级为兜底校准；③建热门商品池（GMV/搜索/加购/波动度打分），按热门/腰部/长尾/冷门分层设定采集频率，实时接口配额优先喂热门型号。
- **解决什么**：根因一（报价可信度）的时效部分——白天看隔夜数据、回查下次才生效、高峰静默丢数据；以及把有限采集算力投到最该新鲜的型号上。

#### A2 供给广度平台化

- **做什么**：让接一家新供应商从改 5+ 处代码变成一份配置即可。
- **怎么做**：供应商插件化——一份配置（适配器 + 字段映射 + 凭证 + 定价规则 + 新鲜度层级）完成接入。
- **解决什么**：扩供应商慢、扩品成本高、追不上云汉广度。

#### 根因一兜底机制（不依赖上游的加购与下单可信化）

- **做什么**：在上游数据天生不准的前提下，用我们可控的手段兜住。
- **怎么做**：下单/询价前强制实时回查（失败明示"需确认"，不回退旧数据冒充现货）；无实时接口的供应商加购/下单触发爬虫回查；自有数据快速生效（即 A1.2）；新鲜度透明化（超旧数据降权或转询价）；同型号挂多家做 fallback。
- **解决什么**：根因一里"最致命"的下单回查失败回退 ES 假装有货——跑单/赔付的真正原因。

### B. 发现与转化引擎（决定流量与转化）

#### B1 搜索范式升级

- **做什么**：从关键字+通配符升级到选型式搜索。
- **怎么做**：型号精确 → 关键词模糊（中文同义词）→ 参数搜索 → 跨供应商比价聚合 → 替代料推荐（pin-to-pin/功能替代/国产化专项）→ BOM 智能配单。
- **解决什么**：只能按已知型号找、搜不到就流失；参数被截断、无替代料导致搜索命中率与转化低。

#### B2 AI 智能化

- **做什么**：AI 贯穿提效。
- **怎么做**：选型助手 / BOM 解析纠错 / 智能替代料 / 报价机器人 / 需求与价格预测。
- **解决什么**：AI 接口刚起步，工程师选型与询价效率低、人工成本高。

#### B3 流量与 SEO

- **做什么**：把代购专区的有限触���做大。
- **怎么做**：型号页 + datasheet/参数页内容 SEO + 工程师社区运营。
- **解决什么**：流量这一乘数当前太弱，有供给也触达不到客户。

### C. 客户与客单价值（决定乘数）

#### C1 客户增长引擎

- **做什么**：补上完全空白的客户经营。
- **怎么做**：CDP + 客户分层（大客户/中小批量/工程师打样）+ 复购引擎（BOM 周期复购/降价/到货提醒）+ RFQ 智能跟进。
- **解决什么**：根因三——把代购当一次性撮合，无分层、无复购、无报价跟进，LTV 乘数近乎 1。**不依赖架构大改，可独立先行。**

#### C2 一站式 PCBA 闭环

- **做什么**：把已通的嘉立创 SMT/BOM 接口做深成闭环。
- **怎么做**：BOM 配单一键转 SMT/PCBA，代购料与 PCBA 流程无缝衔接、入口互导。
- **解决什么**：客单价上不去、一站式入口价值没充分变现。

#### C3 智能定价引擎

- **做什么**：把手工黑箱加价率变成智能定价。
- **怎么做**：竞品比价 + 动态定价（供需/库存/交期/客户分层）+ 毛利优化 + RFQ 自动报价。
- **解决什么**：根因五——定价黑箱、无比价无动态调价，纯利润未被开发。

---

### D. 履约与开放生态（决定可规模性与新渠道）

#### D1 履约供应链中台

- **做什么**：让履约链路透明、可分段优化。
- **怎么做**：询价→采购→物流→报关→入库→发货全链路中台；供应商评级 + 智能寻源（多供应商 fallback）；热门料保税仓。
- **解决什么**：根因四——履约不透明、无法定位哪段慢/哪家差；前半段（供应商发货→报关→入仓）是代购独有瓶颈。

#### D2 开放 B 端平台

- **做什么**：把仅内网的 API 开放给外部。
- **怎么做**：开放 B 端 API（搜索/报价/下单/库存）+ ERP 对接 + 第三方分销 + 供应商入驻。
- **解决什么**：根因五——B 端渠道为零，错失"别人系统帮我们卖货"的分销。

#### D3 行业数据资产

- **做什么**：把仅自用的数据变成对外资产。
- **怎么做**：价格行情指数 / 交期预警 / 缺货榜单，对工程师免费或会员制。
- **解决什么**：数据价值只耗在自用，既不引流也不变现。

## 二、调研点（用真实数据钉死优先级，不靠主观排序）

技术根因已清楚，但"哪个最该先做、投入多大"必须用我方数据证明。每个调研点说清「调研什么 / 钉死什么决策」：

| 调研什么                                 | 钉死什么                                                                                                               |
|------------------------------------------|------------------------------------------------------------------------------------------------------------------------|
| **有效可售 SKU / 搜索零结果率**          | 数据广度是否头号瓶颈 → 决定 A1/A2 是否最优先（名义上亿但鲜活+可搜索的有效量未知；零结果率高需区分是供给问题还是搜索问题） |
| **报价失真率 / 缺货改价取消率**          | 时效与履约的真实损失 → 决定 A1 兜底 / D1 履约的优先级与 ROI（"回查失败假装有货"造成的跑单/赔付规模未量化）               |
| **复购率 / 老客收入占比**                | 客户引擎是否最大杠杆 → 决定 C1 优先级（若我方复购远低于行业，C1 是投入产出最高且不依赖架构大改的方向，应列第一优先）       |
| **各履约段时效分布**（报关/跨境/国内段）   | 履约瓶颈定位 → 决定 D1 改哪段（只有拆到每段才知道是供应商发货慢、报关卡住、还是入仓慢，避免打错环节）                       |
| **资料完整度分布**（参数/图/规格书覆盖率） | 商品资料短板程度 → 决定 A1"数据质量三评分"和资料增强的投入（定位是普遍偏低还是个别供应商拖后腿）                         |

**调研方法统一**：先看真实分布（均值/中位数/分位数）不预设阈值 → 归因树拆到根因 → 量化每个维度的 GMV 损失 → 产出决策矩阵（按"GMV 挽回 ÷ 改造成本"排序即优先级）。

## 三、起步建议

1. **A 节是一条紧耦合的链**：A1（地基）→ A1 治理定位（全量聚合不删）→ A1+（撮合）→ A1++（时效）→ 根因一兜底。其中 **A1 主数据切片① + C1 客户引擎 + 热门商品池** 风险最低、可独立先行，是天然的起步组合。
2. **调研先行**：上述 5 项数据一旦取到，所有改造点的优先级会被重新钉死。建议调研先行，别在数据出来前就把顺序定死。

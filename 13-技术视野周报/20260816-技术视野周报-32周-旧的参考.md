- **发布时间**：2026-08-02 公测，2026-08-07 ARC 验证成绩发布

### 3. 蚂蚁百灵 Ling-3.0-flash 开源：124B 总参数仅激活 5.1B，原生混合线性注意力架构

- **发布时间**：2026-08-05（开源）/ 2026-08-08（华为昇腾适配公告）
- **核心摘要**：蚂蚁集团旗下百灵大模型正式开源 Ling-3.0-flash，定位"极致智能密度、全链路 Agent 闭环与低成本规模化落地"。采用 124B 总参数、5.1B 激活的 MoE 架构，相较上代 1T 级旗舰 Ring-2.6-1T，计算开销仅为其 8.1%。核心创新为原生混合线性注意力架构（KDA 与 MLA 按 5:1 交替堆叠）搭配 1/64 稀疏 MoE 专家路由，长文本计算线性降本。内置 256K 上下文（可扩展至 1M），Artificial Analysis 智能指数 38 分，每任务约 0.04 美元。提供 API、单机私有化（DGX Spark INT4）、高性能部署（昇腾 A2 八卡/A3 四卡）三条路径，MIT 许可证。华为昇腾 0 Day 适配并首发 CANN PyPTO 算子编程框架。
- **热度数据**：GitHub 周榜热门；Hugging Face、ModelScope 双平台开源

### 10. 华为昇腾首发 CANN PyPTO 算子编程框架，重塑大模型算子开发范式

- **发布时间**：2026-08-06（华为计算官方）
- **核心摘要**：华为在昇腾 0 Day 适配蚂蚁百灵 Ling-3.0-flash 的过程中，首次引入 CANN PyPTO 算子编程框架并落地百灵大模型。该框架基于 PTO ISA（虚拟指令集）构建 Tile 编程范式，开发者通过 Tensor 级 API 精准定义计算逻辑，由框架自动完成分片调度、数据搬运、代码生成全流程。结合 CANNBot PyPTO Agent（多智能体框架，将算子开发分解为 7 个 Stage 自动推进），将 KDA 等复杂融合算子的开发调优从传统手工模式升级为系统化、自动化的 Agent 工作流模式，显著缩短算子交付周期。适配全面兼容昇腾 A2、A3 系列，为国产算力支撑前沿大模型从发布到规模化部署提供全流程能力。
- **版本说明**：属于基础软件栈重大能力升级（非 LTS 版本号迭代），核心价值在于算子开发范式的根本性重构

## 三、全行业技术落地标杆案例

### 12. Shopify 用 MySQL 替换 Redis 承担库存预留系统，并成功完成扩容

- **发布时间**：2026-08-09（Shopify Engineering 博客）
- **核心摘要**：背景是 Shopify 的库存预留（inventory reservations）系统原基于 Redis 构建，随着业务规模扩张，Redis 在事务一致性、持久化与跨区域复制上的短板日益暴露。痛点是预留数据丢失会导致超卖，跨数据中心同步成本高昂。方案是 Shopify 工程团队将库存预留系统从 Redis 迁移到 MySQL，通过精心设计的事务模型与分片策略承担了原有的高并发写入负载，并完成了横向扩容。效果数据是该系统在迁移后稳定支撑了 Shopify 量级的库存预留需求，证明在特定事务密集型业务场景下，MySQL 经过合理设计能够替代 Redis 成为更可靠的选择。可复用价值是为"中间件选型应回归业务本质而非盲目追新"提供了头部企业的实证案例。
- **来源**：shopify.engineering/scaling-inventory-reservations，Hacker News 周榜高热度讨论

### 13. 【重大事项】网信办《大型个人信息处理者个人信息保护规定（征求意见稿）》公开征求意见

- **发布时间**：2026-08-07（中国网信网）
- **核心摘要**：国家网信办将前期已公开征求意见的《大型网络平台设立个人信息保护监督委员会规定》《大型网络平台个人信息保护规定》整合完善，形成《大型个人信息处理者个人信息保���规定（征求意见稿）》并公开征求意见，反馈截止 2026-09-07。认定条件包括：处理 1000 万人以上自然人个人信息、提供涉及个人信息处理的重要网络服务、对国家安全/经济运行/社会稳定具有重要影响。被认定者需采取加密、去标识化、访问控制、匿名化等措施，并申报认定进入"大型个人信息处理者清单"。
- **风险提示**：
  - 风险等级：中风险（征求意见阶段，但合规方向明确）
  - 影响范围：所有用户规模超千万的互联网平台与企业级 SaaS 服务商
  - 应对建议：企业 IT 与法务团队应在 9 月 7 日前完成意见反馈；立即盘点自身个人信息处理规模，评估是否触发认定门槛；提前规划数据加��、去标识化、访问控制等合规技术措施改造

### 14. 【重大事项】TP-Link Omada ZTP 15 个漏洞链可组合实现 RCE，Black Hat 大会披露

- **发布时间**：2026-08-05（Black Hat USA 大会）
- **核心摘要**：TP-Link 修复其 Omada 网络设备零接触配置（ZTP）机制中的 15 个漏洞，这些漏洞可与此前披露的漏洞组合利用实现远程代码执行（RCE）。由 Forescout 的 Vedere Labs 研究人员发现并在 Black Hat USA 安全大会公布全部细节。攻击场景包括：仅凭知晓序列号即可完成设备纳管、初始纳管期间使用默认凭证、可预测的序列号、通过未经验证的临时下载链接提供文件。远程攻击者可枚举可预测序���号获取 MAC 地址，识别等待纳管的设备。
- **风险提示**：
  - 风险等级：高风险
  - 影响范围：所有使用 TP-Link Omada 系列网络设备的企业网络（覆盖交换机、网关、AP）
  - 应对建议：立即升级 Omada 控制器与固件至最新版本；排查网络中是否存在使用默认凭证的 ZTP 设备；限制 ZTP 纳管网络的暴露面，禁止管理网段直连公网

### 15. Windows Hello for Business 密钥可被恶意软件滥用，实现 Entra ID 持久化访问

- **发布时间**：2026-08-07（The Hacker News）
- **核心摘要**：Entra ID 研究员 Dirk-jan Mollema 演示证明，已在已登录 Windows 会话中运行的恶意软件可静默使用受害者的 Windows Hello for Business 密钥向 Microsoft Entra ID 认证。攻击者可建立长期云端访问、注册受控设备、获取主刷新令牌（PRT），并在租户策略允许时添加其他认证方式。在 TPM 支持的系统上，攻击者并不提取私钥、恢复 PIN 或触发生物识别提示，而是利用 Windows 票据机制在用户交互登录期间保持私钥操作可用。无需管理员权限，仅需在受害者已登录会话中实现代码执行。
- **风险提示**：
  - 风险等级：中风险
  - 影响范围：所有使用 Windows Hello for Business + Microsoft Entra ID 的企业终端环境
  - 应对建议：加强终端 EDR 监控，关注异常 PRT 申请与设备注册行为；评估条件访问策略，限制新设备注册与认证方式添加；该行为被微软视为 WHfB 的设计结果，短期内不会修复，需从终端防护与身份治理层面加固

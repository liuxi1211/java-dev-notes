# SubAgent上下文隔离与蒸馏实践

> SubAgent（子代理）的本质、与多 Agent 架构的区别，以及上下文打包/结果蒸馏两大工程功力点。相关笔记：[Agent与Loop的本质](Agent与Loop的本质.md)

## SubAgent 的本质

**SubAgent = 带打包好的 prompt + 独立上下文窗口 + 裁剪工具集的一次性 LLM 调用实例**（如 Claude Code / TRAE 的 Task 工具）。

关键特点：

1. **主从关系**：父 Agent 派遣，干完即销毁，一次性
2. **上下文隔离**：中间过程不占主上下文，只回传摘要——省 token、防污染
3. **单向通信**：不能反问，启动拿全指令，跑完一次性汇报
4. **工具集裁剪**：搜索型 subagent 只给读类工具，省 schema token、降风险

## 工程功力在两点

- **上下文打包**：任务自包含（目标/约束/输出格式），子代理"失忆上岗"——带太少瞎干，带太多失去隔离意义
- **结果蒸馏**：内部烧 100K token，主 Agent 只收 500 token 摘要——**收益全在蒸馏比**；让子代理"原样返回所有内容"，隔离就白做了

```
主Agent: "去查 X，按 Y 格式回来"          ← 打包
子代理:  [独立loop: 读→搜→汇总]           ← 隔离执行
主Agent: 收到 500 token 结论              ← 蒸馏回传
```

输出契约要在指令里明确（"只返回文件路径列表+关键行号"），否则回传一大坨照样污染主上下文。

## SubAgent vs 多 Agent

| 维度 | SubAgent | 多 Agent |
|---|---|---|
| 本质 | 具体机制/工具 | 架构模式/概念 |
| 生命周期 | 一次性 | 可长期共存 |
| 通信 | 单向：派遣→汇报 | 可双向多轮 |
| 关系 | 严格主从 | 可对等（编排-执行/对话辩论/流水线） |

SubAgent 是多 Agent 思想的简化落地（只有父子派活，无 Agent 间对话）。Anthropic 立场：复杂对等多 Agent 编排透明度差、难调试、收益不成正比。
